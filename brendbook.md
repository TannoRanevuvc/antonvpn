# CLAUDE.md — AntonVPN WebApp

## 1. Роль и задача

Ты разрабатываешь frontend информационного Telegram WebApp для VPN-сервиса **AntonVPN**.

Нужно переработать существующий монолитный экран в спокойный, премиальный и адаптивный интерфейс согласно брендбуку ниже.

Основная функция WebApp:

1. показать статус подписки;
2. показать дату окончания и оставшееся время;
3. показать QR-код подписки;
4. дать скопировать ссылку подписки;
5. предложить клиент для Android, iOS, Windows или macOS;
6. показать инструкцию подключения;
7. дать перейти в Telegram за помощью.

В приложении **нет**:

- оплаты;
- тарифов;
- регистрации;
- оформления подписки;
- выбора VPN-сервера;
- управления VPN-подключением;
- заявлений о полной анонимности или абсолютной безопасности.

Не добавляй эти функции без отдельного задания.

# 3. Концепция бренда

## Название

Основное написание:

**AntonVPN**

Не использовать:

- Anton VPN;
- ANTON VPN;
- Anton Vpn;
- АнтонВПН.

Внутри URL и username допустимо:

- `antonvpn`;
- `anton-vpn`.

## Концепция

**Quiet Connection / Тихое подключение**

AntonVPN — спокойный технологичный сервис, который не перегружает пользователя терминами, обещаниями и визуальным шумом.

## Позиционирование

> Спокойное подключение без цифрового шума.

## Главная фирменная фраза

> Всё спокойно.

## Характер

AntonVPN должен быть:

- спокойным;
- лаконичным;
- технологичным;
- премиальным;
- понятным;
- сдержанным;
- человечным.

AntonVPN не должен выглядеть:

- агрессивным;
- хакерским;
- детским;
- чрезмерно мемным;
- перегруженным;
- похожим на антивирус;
- похожим на криптовалютный проект.

## Уровень юмора

Уровень юмора: **1–2 из 5**.

Основной интерфейс должен быть нейтральным. Лёгкая ирония возможна только в некритических сообщениях.

# 4. Визуальное направление

## Главная метафора

Вместо щита используется **открытый портал**.

Знак должен состоять из двух простых симметричных или почти симметричных форм. В негативном пространстве между ними может угадываться буква `A`.

Знак передаёт:

- открытый проход;
- соединение;
- доступ;
- спокойное движение;
- букву A как отсылку к Anton.

## Не использовать

- щиты;
- замки;
- ключи;
- глобусы;
- хакеров в капюшонах;
- микросхемы;
- бинарный код;
- кислотный неон;
- чрезмерное свечение;
- сложные градиенты;
- эмодзи вместо UI-иконок;
- декоративные изображения серверов.

## Логотип

Если готового нового SVG-логотипа ещё нет, создай временный минималистичный знак `PortalMark`:

- две мягкие геометрические скобы или дуги;
- между ними открытое пространство;
- знак должен хорошо читаться в размере `20 × 20 px`;
- знак не должен быть похож на щит;
- знак должен работать одним цветом;
- не используй растровый текущий логотип в новом интерфейсе.

Оформи знак отдельным переиспользуемым SVG-компонентом, чтобы его можно было заменить позднее без изменения остальных компонентов.

Пример API компонента:

```tsx
<PortalMark size={32} color="currentColor" />
```

Не вставляй SVG одинаково в несколько файлов. Должен быть один компонент или один SVG asset.

# 11. Карточка статуса подписки

Это главный информационный блок.

## Активная подписка

```text
Всё спокойно

Подписка активна
До 8 августа 2026

Осталось 2 дня
```

## Обычное активное состояние

Если до окончания достаточно времени:

- основной заголовок: `Всё спокойно`;
- текст: `Подписка активна`;
- дата: `До 8 августа 2026`;
- оставшееся время показывать вторичным текстом.

## Скоро закончится

Если осталось мало времени:

```text
Подписка скоро закончится

Активна до 8 августа 2026
Осталось 2 дня
```

Используй предупреждающий цвет, но не красный.

Порог `expiring soon` должен браться из существующей бизнес-логики. Если его нет, вынеси значение в конфигурацию, например 3 дня.

## Неактивная подписка

```text
Подписка неактивна

Вернитесь в Telegram-бот, чтобы проверить доступ.
```

## Неизвестный статус

```text
Не удалось определить статус

Обновите страницу или вернитесь в Telegram-бот.
```

Не придумывай дату или статус, если данные отсутствуют.

# 12. Ссылка подписки и QR-код

Заголовок секции:

**Ссылка подписки**

Структура:

```text
Ссылка подписки

[QR-код]

https://anton-vpn.../sub/••••••••

[Скопировать ссылку]
```

## QR-код

Требования:

- генерируется из полной ссылки подписки;
- чёрный код на белом фоне;
- без градиентов;
- без встроенного логотипа;
- с достаточной quiet zone;
- размер должен быть удобен для сканирования;
- визуальная подложка QR-кода всегда белая;
- значение ссылки не должно отправляться во внешние QR API;
- QR-код должен генерироваться локально в браузере.

Если ссылка отсутствует:

- не показывать пустой или невалидный QR-код;
- показать понятное состояние ошибки;
- не давать нажимать кнопку копирования.

## Поле ссылки

- визуально показывать сокращённую ссылку;
- копировать полное значение;
- использовать `text-overflow: ellipsis`;
- ссылка не должна ломать layout;
- не выводить полную секретную ссылку в console;
- не отправлять ссылку в аналитику;
- не помещать ссылку в error reporting payload.

При необходимости добавь кнопку показать/скрыть полную ссылку, но по умолчанию скрывай чувствительную часть.

## Копирование

Основная кнопка:

```text
Скопировать ссылку
```

После успешного копирования:

```text
Скопировано
```

Требования:

- состояние успеха сохраняется около 2 секунд;
- ширина кнопки не меняется;
- иконка копирования меняется на галочку;
- показать доступное текстовое подтверждение;
- использовать Clipboard API;
- предусмотреть fallback для старых WebView;
- не оставлять временный DOM-элемент после fallback-копирования.

Ошибка:

```text
Не удалось скопировать ссылку. Выделите её вручную.
```

- тонкая граница;
- основной текст;
- заметный focus state.

## Карточки

- радиус: `16–20px`;
- padding на мобильном: `20px`;
- тонкая граница;
- без тяжёлой тени;
- в тёмной теме карточки разделяются поверхностью и границей;
- в светлой теме допускается мягкая тень.

## Поля

- минимальная высота: `48px`;
- радиус: `12px`;
- длинный текст обрезается;
- focus ring не удалять;
- ссылка должна быть доступна для выделения мышью.

## Status badge

Badge может использоваться как дополнительный элемент, но не должен быть единственным сообщением о статусе.

# 18. Сетка и адаптивность

## Mobile first

Основной сценарий — Telegram WebApp на смартфоне.

```css
.page {
  width: 100%;
  min-width: 0;
  min-height: 100%;
  background: var(--color-bg);
  color: var(--color-text);

.container {
  width: min(100%, var(--content-width));
  margin-inline: auto;
  padding-inline: 16px;
}
```

## Размеры

- минимально поддерживаемая ширина: `320px`;
- основной внутренний отступ: `16px`;
- расстояние между секциями: `24px`;
- один столбец на мобильном;
- максимальная ширина контента: `720px`.

## Более широкие экраны

На tablet/desktop:

- центрировать страницу;
- QR-код и ссылку можно расположить в две колонки;
- карточки клиентов можно расположить по две в ряд;
- инструкция остаётся последовательной;
- не растягивать текст на всю ширину окна.

## Safe Area

Учитывать Telegram и iOS safe areas:

```css
.app {
  padding-top: env(safe-area-inset-top);
  padding-bottom: env(safe-area-inset-bottom);
}
```

Если Telegram SDK предоставляет viewport insets, используй их корректно и не удваивай отступы.

# 20. Анимации

Анимация должна объяснять состояние, а не украшать экран.

- смена состояния кнопки;
- мягкое открытие портала;
- плавное переключение темы;
- короткий toast;
- skeleton loading.

- обычная длительность: `160–240ms`;
- анимация логотипа: до `500ms`;
- easing: `cubic-bezier(0.22, 1, 0.36, 1)`;
- нажатие кнопки: scale до `0.98`.

- постоянные пульсации;
- яркие вспышки;
- неоновое свечение;
- бесконечные декоративные анимации;
- сложный parallax;
- тяжёлые canvas-анимации.

Поддерживать:

```css
@media (prefers-reduced-motion: reduce) {
```

Говорить коротко, понятно и без драматизации.

# 25. Данные

Адаптируй модели к существующему API. Не меняй backend-контракт без необходимости.

Ориентировочная frontend-модель:

```ts
type SubscriptionStatus = "active" | "expiring" | "expired" | "unknown";

type Platform = "android" | "ios" | "windows" | "macos";

interface SubscriptionData {
  status: SubscriptionStatus;
  expiresAt?: string;
  daysRemaining?: number;
  subscriptionUrl?: string;
}

interface ClientOption {
  id: string;
  name: string;
  platform: Platform;
  description?: string;
  recommended?: boolean;
  downloadUrl?: string;
}

interface GuideStep {
  id: string;
  text: string;
}

interface AntonVpnPageData {
  subscription: SubscriptionData;
  clients: ClientOption[];
```

Эта модель — ориентир, а не требование переписать существующий API.

- логировать её в console;
- отправлять её в аналитику;
- отправлять во внешний сервис QR-кодов;
- добавлять её в query string сторонних URL;
- включать в текст ошибок;
- сохранять без необходимости в localStorage;
- показывать полностью по умолчанию.
